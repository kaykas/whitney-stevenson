The blog index and post templates already linked correctly; only the homepage was orphaned. | RULE: every route must ship at least one crawlable `<a href>`/`<Link>` to another URL — fragment-only anchors and `mailto:` don't count. The real defect was **process**: the 09-07 rule prescribed a *manual* `grep -o 'href="[^"]*"' .next/server/app/index.html`, which nobody runs on a routine edit, so the site had no way to fail fast and the same Ahrefs finding kept re-firing off crawl data collected before the fix shipped. | RULE: a rule that depends on a human remembering to grep is not a guardrail. [2026-09-09] | Ahrefs/GSC flagged "Meta description too long" (Warning severity, 6 URLs) — `/` plus all five `/blog/*` posts | The `<meta name="description">` for every affected route was 200–308 characters against a ~160-character SERP budget. Root cause was a single overloaded field: `Post.description` in `src/lib/posts.ts` was doing double duty as both the **visible lede** rendered on the post page (`post-lede`) and the blog index, *and* as the meta/OG/Twitter/JSON-LD description. Long dek copy is a legitimate design choice; long meta copy is an SEO defect. Because one field served both, there was no way to fix the meta tag without shortening visible copy, so it was left long. `/` had the same shape — one `DESCRIPTION` const in `layout.tsx` at 218 chars. `/blog` (139) was already fine, which is exactly why the report said 6 URLs and not 7. | RULE: never let one string serve both visible copy and a meta tag — they have different length budgets and different audiences. `Post` now carries a separate required `metaDescription` (≤155 chars) used for `metadata.description`, OpenGraph, Twitter and BlogPosting JSON-LD; `description` stays the visible lede and its length is a design call. Enforced automatically, per the 2026-09-09 outgoing-links precedent that a rule needing a human to remember it is not a guardrail: `scripts/check-meta-descriptions.mjs` reads the **prerendered HTML** (not the source modules, so it catches metadata composed anywhere — layout defaults, route `metadata`, `generateMetadata`) and fails the build if any crawlable route has zero or multiple description tags, or one outside 70–160 chars. HTML entities are decoded before measuring — `&#x27;` is one character to a crawler, not six. Wired as `postbuild` alongside the link check so both run inside `npm run build` locally and on Vercel; standalone via `npm run check:meta`. Negative-tested: restoring a 358-char description fails the build with a non-zero exit.
